# 一锅出 first-customers 试用追踪

目标不是“发很多人”，而是验证：真实做饭的人会不会在第二天自己回来再用。

线上链接：<https://yiguochu.pages.dev/>

## 本周唯一目标

- 找 5 个真实做饭的人，一对一发出试用邀请。
- 至少拿回 3 份真实反馈。
- 关键指标：第二天主动回访人数。

## 熟人邀请文案

```text
我做了个小工具，专门解决“今天吃什么”：填一下家里有什么，它会给一道一锅/一碗主餐，尽量把主食、蛋白和蔬菜配齐。

你这周做饭前能不能帮我认真试一次？不用夸我，只告诉我三件事：
1. 它给的菜你想不想做；
2. 做起来哪里麻烦；
3. 第二天你还会不会再打开。

链接：https://yiguochu.pages.dev/
```

## 统计口径

测试者打开页面后，如果愿意配合，可以在手机浏览器 console 运行：

```js
__yiguochuStats()
```

重点看：

- `gen`：点了几次生成
- `gen_ok`：成功几次
- `choose`：有没有点“就吃这个”
- `swap`：换一换次数
- `feedback_ate` / `feedback_skip`：第二天反馈

## 决策规则

- 5 人里有 3 人愿意认真试：继续找下一圈。
- 5 人里有 2 人以上第二天主动回来：产品方向有信号。
- 大家只夸、不回来：先别加功能，查为什么没有真实使用。
- 频繁失败或等待太久：先修稳定性，不做获客扩张。

## 待验证想法（先记着，别在发出去前做）

pilot 期间冒出来的产品改进。**触发条件没到就不做**——避免在零真实反馈时凭空完善（这是这个项目最大的执行陷阱）。

| 想法 | 触发条件（满足才做） | 备注 |
|---|---|---|
| 一周汇总里显示更全营养（铁/锌/镁/钾/维C/维D），单餐保持 6 项主项 | 有人用满 7 天 **且** 主动反馈想看更全营养 | 数据已全算（在 `d.nutrients`），只差周维度 UI；周维度才有累计、单餐别堆。位置判断是对的，缺的是触发它的真实用户 |
| 看菜谱→做饭的衔接（购物清单 / 复制食材 / 做饭大字模式） | 有人反馈"想做，但中间嫌麻烦没做成" | codex 旅程审查指出的最大断点 |
| 留存钩子（添加到主屏引导 / "明天按你反馈调整"承诺） | 第二天回访率偏低 **且** 用户说"会用但忘了打开" | 留存信号弱、且原因是"忘"时才补 |
| 「一日量」口径决策：逼模型给足 1800kcal，还是改叫"一顿正餐+" | 试用者反馈"量不够吃 / 量正好"的倾向明确后 | 实测模型交付 ~1000kcal(58%)，克数化 prompt 已从 43% 拉到 58%，再往上逼收益递减；三档诚实文案已兜底。本质是产品定位问题，不是技术问题 |
| 首屏价值预览（填表前先看到"你会得到什么样的一锅"示例） | 试用者反馈"一开始不知道这是干嘛的" 或 首次生成前流失明显 | codex 与旅程评审都提过；需要真实第一印象数据才能设计对 |
