# 一锅出产品原则

1. 个性化不是迎合，而是推荐用户真正需要和适合的方案。
2. 尊重显性约束，优化隐性需求。
3. 长期目标可以宏大，但当前架构只服务当前目标。
4. 预期基础模型持续进化，不提前建设复杂推荐平台、用户画像或多 Agent。
5. 只积累真实需求、决策理由和真实结果，不用点击行为冒充做饭结果。

这些原则用于约束当前产品和技术决策。本阶段不增加账号、营养追踪、云端用户数据、自然语言场景、多 Agent 或新菜谱。

## 当前唯一产品边界：先把电饭煲菜饭做好

- 用户默认家里有米，只需选择配菜、份数和忌口。
- 公开 Preview 只推荐一次密闭煮饭周期可完成的电饭煲菜饭；面条、粥、汤饭、剩饭翻炒和多锅计划不进入这条路径。
- 候选来自经过机器校验的菜饭目录，使用固定自然菜名、明确米水比例、受控动作和安全终点；不拿食材名机械拼接菜名，也不让 DeepSeek 自由决定组合。
- A 级（主食、蛋白质、纤维）优先，B 级诚实展示；只有单一营养角色的 C 级不作为普通候选。
- 当前架构只服务这一件事。旧 Planner、Legacy 生成器和地域研究资产可以留在源码与证据层，但不得在 rice-meal Preview 的公开交互里偷偷扩张成平台。

“简单”不是少做校验，而是把复杂性留在目录、比例、安全和发布门里，让用户只需要回答“家里有什么配菜”。
