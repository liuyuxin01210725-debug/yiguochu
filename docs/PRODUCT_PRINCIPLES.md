# 一锅出产品原则

1. 个性化不是迎合，而是推荐用户真正需要和适合的方案。
2. 尊重显性约束，优化隐性需求。
3. 长期目标可以宏大，但当前架构只服务当前目标。
4. 预期基础模型持续进化，不提前建设复杂推荐平台、用户画像或多 Agent。
5. 只积累真实需求、决策理由和真实结果，不用点击行为冒充做饭结果。

这些原则用于约束当前产品和技术决策。本阶段不增加账号、营养追踪、云端用户数据、自然语言场景或多 Agent。

## 当前唯一交付物：有真实来源的一锅出菜谱目录

- 只收集能追溯到独立真实来源的具名菜谱；项目自由组合的名字不得冒充传统或已有菜谱。
- 来源只能支持它实际证明的身份、食材、用量、液体、做法、器具、时间或安全事实；不得用一条菜名来源补齐整套做法。
- 当前先完成目录和缺口清单，交给人工审阅；未批准前不开始新公开交互。
- 食材选择、份数、忌口规划、Planner 组合和 AI/DeepSeek 生成全部冻结；不用技术组合来掩盖菜谱来源不足。
- 现有 72 道 recipe、Planner、Legacy 生成器和 Preview 运行目录仅作历史证据与技术资产，不是当前产品承诺。

“简单”不是少做校验，而是先把“这道菜真实存在、来源能证明什么”做对，再谈如何交给用户。
