# 六道传统一锅主食原创草案设计

日期：2026-07-17

状态：用户已确认设计，待用户复核书面规格后编写实施计划。

## 目标

把六个已完成文化事实溯源的候选，写成不进入线上运行时的“一锅出原创标准配方草案”。草案的作用是把传统方向变成可审查、可试做的家庭一锅主餐底稿，而不是把第三方配方换词后搬入产品。

首批六道：

1. 上海咸肉菜饭
2. 南京矮脚黄香肠菜饭
3. 泉州浥饭（油饭）
4. 北方豆角焖面
5. 新疆羊肉抓饭
6. 贵州侗家社饭

## 非目标

- 不修改 `tools/data/recipe-library.json`、`worker/src/worker.js`、`ai_proxy.py`、`index.html` 或手机端显示。
- 不把任何草案标为 `approved`，不部署到 preview 或 production。
- 不复制文化页面、地方志或任何第三方作者的食材表、克数、时序、步骤、图片或文字表达。
- 不把文化来源当作营养、安全、口味或“正宗”保证。

## 数据边界

新增独立文件 `tools/data/recipe-drafts.json`，仅供编辑、试做和人工审核。它与 `tools/data/recipe-candidates.json` 的关系是：

`候选文化事实 → 原创结构化草案 → 试做记录 → 人工审核 → 正式生产菜谱`

worker 和本地代理继续只读取 `recipe-library.json`；任何草案 ID 都不得出现在生产库中。

每道草案必须包含：

- `id`、`candidate_id`、`status: "draft"`、`name`、`region`、`form`；
- 以自己的话写的 `adaptation_summary`，明确它是家庭一锅完成的改编；
- `core_ingredients`、`optional_ingredients`、`substitution_slots`，不允许模型自行扩大替换；
- `draft_ratio_rules`：一锅主食与液体的相对逻辑、加料时机和必要的家庭份数范围；不引用外部来源的原始克数；
- `technique_outline`：仅写原创的高层流程，不复制来源步骤；
- `safety_and_quality_gates`：每道的熟制、骨刺、腌腊钠、出水或糯米等风险；
- `trial_requirements`：需记录的锅具、份数、实际用量、时长、成品状态和修订原因；
- `candidate_id`：关联候选册内已有文化事实依据；运行时或审核时沿该 ID 读取依据，不重复拷贝网页正文。

## 原创标准化原则

1. 传统菜名、地域、常见核心食材和高层技法用于确定方向；具体配方由项目原创。
2. 不为了使用用户全部库存而强行塞入无关食材；不适合的食材须允许被明确舍弃。
3. 替换必须是明确的槽位，写清替换对象和可用范围。
4. 草案不包含营养数值；日后正式生成仍走台湾库、本地库和 AI 估算标记的既有机制。
5. 用户可见时使用“参考某地传统风味的一锅出改编”，不用“正宗”“原方”或“认证配方”。

## 六道草案的风险层级

| 草案 | 风险级别 | 重点审核 |
| --- | --- | --- |
| 上海咸肉菜饭 | moderate | 咸肉预处理、钠、青菜出水、米饭口感 |
| 南京矮脚黄香肠菜饭 | moderate | 腊肠钠和脂肪、青菜出水、米饭口感 |
| 泉州浥饭（油饭） | moderate | 干货复水、猪肉熟制、海味/过敏原默认不进入首版 |
| 北方豆角焖面 | high | 生豆角彻底熟透、肉熟制、面条吸水与糊底 |
| 新疆羊肉抓饭 | high | 羊肉熟制、胡萝卜与米的时序、清真语境不作泛化承诺 |
| 贵州侗家社饭 | high | 腊肉钠、社蒿菜的可得性与明确替代、地方菜名尊重 |

## 草案晋升条件

草案不等于可用菜谱。某一道升级为生产基础菜谱前，至少需要：

1. 对应候选的文化事实依据有效；
2. 原创配方经过结构审查，替换和不建议组合明确；
3. 完成该风险级别要求的真实试做并保留记录；
4. 生肉、禽蛋、豆角、骨刺或过敏原的安全节点可验证；
5. 具备项目自有 canonical 来源页，再通过既有 `check-recipes`、回归和人工审核；
6. 遵守当前 Phase A exit gate，未获用户批准前不进入 150–200 道生产扩展或部署。

## 验收条件

- 六道草案全部存在，且 `status` 都是 `draft`；
- 每道草案恰好映射一个已存在的 `candidate_id`，不重复；
- 草案库不得含 `approved`，不得被 worker 或本地代理加载；
- 每道均有原创改编说明、替换边界、草案比例规则、风险门槛、试做要求和候选依据引用；
- 自动检查在候选不存在、ID 重复、状态错误、缺安全/试做字段或草案混进生产库时失败；
- 既有候选检查和正式菜谱检查继续通过。
