# 中国一锅主餐全国地域地图 V2 设计

日期：2026-07-26

状态：设计已确认，等待用户审阅正式规格

替代范围：本规格扩展并取代 `2026-07-25-china-one-pot-regional-atlas-design.md` 中的全国骨架、节点结构、研究顺序与东北首轮方案。原文中关于产品边界、来源许可和研究不等于上线的原则继续有效。

适用范围：Draft PR #1 的后续实施规划。本规格不授权新增生产 recipe、修改 Planner 组合逻辑、部署 Preview、部署 production 或合并 PR。

## 1. 决策摘要

地域扩展采用“双轴地图”，而不是逐省堆固定菜谱：

1. 地域轴完整覆盖中国 34 个省级行政区，包括香港、澳门、台湾；
2. 技法轴描述跨地域复用的一锅结构；
3. 城市、县域和民族饮食作为地域节点或覆盖标签下钻；
4. 地方原型先进入研究层，不自动成为生产菜谱；
5. 全国骨架先完整建立，再按地域逐批研究；
6. 每批最多研究一个地域、一个主要技法家族和四个原型；
7. 地域研究可以只产生 evidence、taxonomy、Ratio DSL 或内容结论，不要求新增 recipe。

## 2. 第一性原理

“一锅出”是家庭结果概念，不是器具教条。合格方向应同时满足：

- 主要主食和核心配菜由一口主要锅具或一个主要烹饪设备完成；
- 减少洗切、转锅、看火和收拾负担；
- 形成一顿合理、好吃、可完成的家庭主餐；
- 尽量消化常见库存食材，但不强行组合；
- 家庭适配不掩盖与传统原型的差异；
- 地域、核心食材、技法、比例和安全边界可分别追溯；
- DeepSeek只表达确定方案，不决定地域归属、槽位、替换、比例或安全规则。

## 3. 非目标

本阶段不做：

- 为 34 个省级行政区平均分配菜谱数量；
- 为填满地图而编造地方菜名；
- 将 24 个现有研究题目直接晋升为生产 recipe；
- 一次性研究全国所有地方菜；
- 把地域原型全部转成 template；
- 建设完整饮食知识图谱；
- 复制许可不明的完整步骤、原文或图片；
- 新增账号、用户画像、营养追踪或多 Agent 运行时；
- 修改公开产品流程或部署任何环境。

## 4. 双轴模型

### 4.1 地域轴

```text
全国
└─ 地域板块
   └─ 省级行政区
      └─ 城市／县域／民族地区
         └─ 地方原型
            └─ 常见变种
```

行政区节点保证全国不漏项；地方原型和变种只在有事实依据时添加。没有合格候选的省份保留为 `skeleton_only`，不强行补菜。

### 4.2 技法轴

每个地方原型必须归入一个主要技法家族，也可以附带一个次要技法标签。同一技法可跨地域复用，同一地域可包含多个技法。

### 4.3 民族与文化覆盖层

蒙古族、回族、藏族、维吾尔族、壮族、苗族、侗族、傣族、畲族和客家等不作为脱离地域的孤立菜谱库。它们通过 `cultural_overlays` 连接相应省份、城市和原型，允许跨省关联但不重复复制节点。

## 8. 状态机

```text
skeleton_only
→ research_queue
→ fact_checked
→ family_modeled
→ product_decided
→ preview_candidate

任一步均可 → rejected
```

- `skeleton_only`：只有地域位置和研究问题；
- `research_queue`：已发现候选，尚未完成事实核实；
- `fact_checked`：地域、名称、核心食材和高层技法已核实；
- `family_modeled`：技法家族、变种和家庭适配边界已整理；
- `product_decided`：已确定产品去向；
- `preview_candidate`：比例、安全和家庭操作已结构化，等待 Preview 与人工验证；
- `rejected`：不适合家庭一锅产品，并保留结构化原因。

禁止 `research_queue` 或 `fact_checked` 直接成为生产 recipe。

## 9. 产品去向

每个完成研究的原型必须选择一个或多个明确去向：

- `recipe_evidence`：为可信 recipe 提供技法、安全、比例或来源依据；
- `template_evidence`：证明现有或未来通用模板的组合结构；
- `taxonomy_rule`：补充食材类别、形态、含水、熟制或替换规则；
- `ratio_rule`：补充机器可执行的主食、液体和份量规则；
- `content_only`：有文化价值但不适合当前产品；
- `rejected`：来源、家庭价值、安全或适配不成立。

研究完成后允许零生产变更。

## 10. 70/30 研究优先级

### 10.1 产品价值：70 分

- 高频 pantry 食材缺口：0–30；
- 合理覆盖 2–4 种食材：0–20；
- 家庭设备、时间和操作负担：0–10；
- 增加真实不同 plan，而非只增加菜名：0–10。

### 10.2 地域价值：30 分

- 补当前地域空白：0–10；
- 地方代表性和来源可核实性：0–10；
- 原型与变种关系清晰：0–10。

### 10.3 风险扣分：0–30

- 水量、比例或时间难确定；
- 特殊食材难买且不能合理替换；
- 高风险熟制或预处理复杂；
- 家庭化明显损害传统身份；
- 与现有家族同构，只增加固定菜名。

`total_score = product_score + regional_score - risk_penalty`。低于 60 分原则上不进入产品研究，但可以保留为 `content_only` 或 `rejected`。分数不能越过来源和安全硬闸门。

## 11. 来源标准

### 11.1 来源分级

- A 级：政府、地方志、非遗、地方标准、正式出版物；
- B 级：权威媒体、博物馆、研究机构；
- C 级：社交内容、个人菜谱、餐馆菜单，只用于发现和观察变种。

### 11.2 `fact_checked` 门槛

至少满足下列一种：

1. 一条 A 级来源直接证明地域、原型和核心结构；
2. 一条 A 级来源加一条独立 B 级来源共同证明；
3. 找不到 A 级来源时，两条独立 B 级来源加明确的来源不足说明，只能停留在研究层。

来源证明必须按范围拆开：地域、名称、核心食材、高层技法、传统变种不能互相代替。家庭比例、设备适配和安全步骤必须独立结构化和验证。

### 11.3 许可边界

- RecipeDB 只用于研究发现；
- GitHub 代码许可不自动授权其中汇总的菜谱；
- 不复制完整步骤、原文或图片；
- 公开社交内容不单独支持生产批准；
- `approved` 与 `auto_approved` 继续遵守项目现有来源和人工评审边界。

## 12. 全国骨架完成标准

阶段 0 完成必须同时满足：

1. 34 个省级行政区恰好各有一个骨架节点；
2. 13 个地域板块无漏项、无重复归属；
3. 11 个技法家族均有机器记录；
4. 现有 72 道生产 recipe 全部映射到地域板块和技法家族；
5. 现有 24 个研究候选全部映射到省份或明确标记地域粒度不足；
6. 每个空白省份有结构化研究问题或明确的暂不研究原因；
7. 民族与文化覆盖标签不复制原型节点；
8. 输出地域覆盖、技法覆盖、pantry 食材缺口和来源状态报告；
9. 所有未核实内容保持 `skeleton_only` 或 `research_queue`；
10. 阶段 0 不改变生产 recipe、template、taxonomy、Ratio DSL、Planner 或 DeepSeek 链路。

“地图完成”不等于“每个省都有菜谱”。

## 14. 分轮扩展顺序

### 第 0 轮：全国骨架

- 建立 34 个省级节点；
- 映射现有 72 道生产菜单；
- 归位现有 24 个研究候选；
- 生成全国空白矩阵；
- 不新增生产 recipe。

### 第 1 轮：优先补产品缺口

1. 东北；
2. 山东；
3. 中原；
4. 川渝；
5. 云贵；
6. 京津冀与晋蒙。

这些地域优先补鸡肉、排骨、猪肉、豆角、土豆、白菜、菌菇、豆腐和面条等常见组合。现有 24 个研究题目是入口，不是预定上线清单。

### 第 2 轮：整理已有强势区域

1. 江南；
2. 闽台；
3. 岭南与港澳；
4. 长江中游。

重点是合并菜饭、咸饭、油饭、煲仔饭和社饭的同构变种，提取共享 evidence、槽位和比例规则。

### 第 3 轮：复杂地域与覆盖层

1. 西北；
2. 青藏；
3. 跨省民族饮食覆盖层。

这些方向涉及肉类部位、杂粮、特殊器具、高原食材和节庆做法，来源与家庭适配风险更高。

## 15. 单轮研究容量

一次只研究：

- 一个地域板块；
- 一个主要技法家族；
- 最多四个地方原型；
- 至少十组真实家庭食材旅程；
- 一份产品去向结论。

研究完成后必须先合并同构变种，再讨论生产接入。

## 16. 东北首轮设计

### 16.1 范围

建立辽宁、吉林、黑龙江三个省级节点。第一家族只研究 `stew-with-staple`，不同时扩展其他东北饭面。

### 16.2 事实入口

黑龙江省政府公开资料记录铁锅内的排骨或鸡块、土豆和玉米，以及锅边同时烀制的玉米饼和小花卷，可作为地域、核心食材和高层技法的第一条 A 级入口：

<https://www.hlj.gov.cn/hlj/tsms/202501/c00_31797990.shtml>

该来源不自动证明豆角、粘卷子、鱼豆腐组合、家庭锅比例或完整安全步骤，相关事实必须另行核实。

### 16.3 四个研究题目

1. 鸡肉、蘑菇、土豆配锅边主食；
2. 排骨、豆角配粘卷子；
3. 排骨、豆角配玉米面饼；
4. 鱼、豆腐、耐炖蔬菜配玉米面饼。

它们是研究题目，不是四条生产 recipe。

### 16.4 暂定家族结构

```text
stew-with-staple

protein:
- chicken
- pork_ribs
- fish（独立安全分支）

stew_vegetable:
- green_beans
- potato
- cabbage
- mushroom

staple:
- corn_dough_cake
- wheat_flower_roll
- sticky_roll
```

玉米面饼、花卷和粘卷子不能仅因都属于面团而共用比例。鱼、鸡肉和排骨不能共用熟制时间。豆角必须有充分熟制规则。普通家庭锅必须验证蒸汽空间和锅边主食的摆放容量。

### 16.5 研究顺序

1. 鸡肉、蘑菇、土豆配锅边主食；
2. 排骨、豆角配粘卷子；
3. 排骨、豆角配玉米饼；
4. 鱼、豆腐、蔬菜配玉米饼。

前两项兼顾常见库存和地域辨识度；鱼类因时间和安全差异最后研究。

### 16.6 东北轮完成门槛

- 辽吉黑三个省级节点建立；
- 四个题目完成地域、名称、核心食材和高层技法核实；
- 同构变种完成合并；
- 玉米饼、花卷和粘卷子建立分离的比例与形态状态；
- 鸡肉、排骨、鱼和豆角安全端点明确；
- 至少十组家庭食材旅程完成静态与人工评审；
- 给出六类产品去向之一；
- 不要求新增 recipe。

## 17. 真实验收场景

阶段 0 至少验证：

1. 34 个省级节点无漏项和重复；
2. 香港、澳门、台湾存在独立节点；
3. 辽吉黑都在东北板块；
4. 青海和西藏都在青藏板块；
5. 民族标签跨省关联时不复制原型；
6. 一条 recipe 可同时关联地域与技法；
7. 一条研究候选不能进入生产菜单；
8. 无来源节点不能超过 `research_queue`；
9. 没有合格候选的省份仍保留 `skeleton_only`；
10. 24 个现有研究题目全部归位；
11. 72 道生产 recipe 全部归位；
12. 同一技法的地域变种可以合并为家族；
13. 一个地方原型可以只产生 `content_only`；
14. 评分高不能越过来源门槛；
15. 东北鱼类候选不能复用排骨的时间和安全规则；
16. 生米、熟饭、糯米、面条、粉丝和面团状态保持分离；
17. 阶段 0 构建物不进入 `dist`；
18. 阶段 0 不改变 Planner 响应；
19. 地图报告明确区分现有生产菜单与研究候选；
20. “地图完成”不能被描述为“全国菜谱均已验证”。

## 18. 成本与研究控制

- 地图构建和候选评分不调用 DeepSeek；
- 来源研究优先使用公开资料，不进行批量付费生成；
- 每个原型的 DeepSeek 表达验证最多一次，且只在进入 Preview 后发生；
- 失败不自动重试；
- 同构变种在研究层合并，避免线性增加调用和人工评审；
- 每轮最多四个原型，防止全国研究失控。

## 19. 实施边界

下一份实施计划只包含第 0 轮：

1. 结构化 13 地域、34 省级节点和 11 技法家族；
2. 建立 atlas schema 与 validator；
3. 映射现有 72 道 production recipe；
4. 映射现有 24 个 research candidate；
5. 生成全国地域、技法、pantry 与来源空白报告；
6. 接入只读 freshness gate；
7. 不修改 recipe、template、taxonomy、Ratio DSL、Planner、Worker、前端或 DeepSeek 链路；
8. 不部署、不合并 PR。

阶段 0 交付并经用户审阅后，才为东北首轮编写独立研究计划。
