# 成熟地方菜上线规则

## 适用范围

本规则用于把可追溯的成熟地方一锅菜，整理为一锅出正式库中的项目原创标准配方。它不把第三方网页、菜谱书、RecipeDB 或社交内容直接带入正式运行包，也不改变营养数据必须经现有权威查表机制取得的规则。

## 来源、传统事实与原创标准化

传统事实可追溯：候选册可记录菜名、地域、常见食材和高层技法，用来说明一项地方饮食传统为什么值得被整理。这些文化事实是发现与核验依据，不是第三方菜谱文字、配方、图片、精确克数、时长或步骤的复制许可。

正式条目是项目原创标准配方。项目基于传统事实自行确定家庭份数、食材边界、比例逻辑、下锅顺序、替换槽、安全规则和适配说明，并在一锅出第一方 canonical 页面公开项目署名与对应的文化候选 ID。不得把“传统”“正宗”或模型生成本身当作口味、安全或授权保证。

## 晋升判断

成熟地方菜不要求逐道真人试做，作为一条统一的上线前置门槛。满足下列条件时，可以晋升为正式条目：

1. 关联文化事实可追溯，候选、草案和正式条目的映射完整；
2. 正式条目是经审查的项目原创标准化，不复制第三方表达或精确操作数据；
3. 核心食材、做法、比例与替换边界明确，且能通过项目的来源、schema、回归和晋升闸门；
4. 生肉、禽蛋、豆角、海鲜、骨刺、过敏原、腌腊与保存等风险已有明确的熟制或处置规则；
5. 第一方 canonical 来源页、项目署名和所需来源字段完整。

`approved` 表示上述结构、来源与安全规则已通过项目审核；项目不伪称已经完成真人试吃，也不承诺每个家庭、锅具或食材品牌都会得到同一口感。

晋升产物的状态为 `auto_approved`（自动闸门通过、待人工评审）：它只表示结构、来源与安全规则通过了自动闸门，不表示人工批准或真人试做。`auto_approved` 条目必须经 `docs/recipe-validation-review.md` 人工评审表逐条通过后，方可改为 `approved`；在此之前不得对外宣称已获人工批准。

## 不可晋升的输入与替换

食材身份不明、名称无法落到明确食品级食材、或替换会改变核心技法的条目，不得晋升。`经核验`、`未知野菜`、`地方植物`等占位式说法不能充当可用食材身份。

替换必须写入结构化替换槽，并明确原位食材与允许范围。常见、名称明确且不改变核心技法的适配可以保留；会把主料、液体、色源、包裹材料或熟制方式换成另一种技术路径的适配必须拒绝或重新审查。

## 试做与上线后的质量改进

真实试做不是成熟地方菜逐道晋升的统一硬门槛，但仍是优化口感、火候、器具适配、出水控制和替换边界的重要方法。项目不伪称已经完成未发生的试做。

上线后应收集用户查看、选择、完成烹饪和反馈等信号，优先复核高频、低评分、失败或产生安全疑问的条目；必要时修订项目原创标准配方、收紧替换边界，或撤回有问题的正式条目。任何反馈优化都不能绕过既有安全、营养、来源和部署闸门。

## 仍然有效的上线闸门

本规则不放宽既有 Phase A、静态回归、live smoke、移动端、来源或人工审核要求。任一必要闸门未通过时，不得宣称已经正式上线，也不得部署到 production `main`；只能按项目部署规则处理预览验证。
