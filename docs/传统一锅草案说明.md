# 传统一锅草案说明

## 用途与运行时边界

`tools/data/recipe-drafts.json` 是编辑、试做和人工审核使用的原创草案库。当前共有 30 道草案，全部为 `draft`，生产可用 0 道。

草案不进入运行时；前端、worker 与本地代理均不得加载草案库。

## 原创配方与传统事实的边界

候选册中的菜名、地域、常见核心食材和高层技法是可核验的传统事实，只用于确定创作方向和追溯依据。它们不是可直接复刻的配方授权。

每份草案都必须是项目独立编写的原创标准配方：独立确定家庭份数、比例逻辑、下锅顺序、替换槽位、适配边界和安全门槛。不得复制或改写第三方页面的文字、图片、食材表、精确克数、时长、时间安排或完整步骤；不得把“传统”“正宗”“原方”当作安全、口味或可用性的保证。

## 真实试做与记录

草案不等于可用菜谱。当前尚无完成的真实试做。每次真实试做须保留草案 ID、日期、试做人、锅具、份数、实际用量、液体比例、总时长、下锅顺序、成品状态、熟制或安全观察，以及修订原因。

- low：完成一次可复核的真实试做，记录米面熟度、口感和一锅完成性；再做常规结构与适配审核。
- moderate：除上述记录外，至少验证火候、吸水比例、分步下锅顺序、出水控制或替换边界；出现偏差须记录修订后复测结果。
- high：除上述记录外，必须逐项记录生禽肉、鸡蛋、海鲜、骨刺、豆角、腌腊或名称不明地方食材的原料身份、可食部位、熟制证据、过敏原、盐分及保存风险；完成额外安全审查与真实试做后才可进入人工审核。

风险等级只用于确定试做深度，不能自动放行。任一安全或质量门槛未满足时，草案保持 `draft`。

## 晋升到生产菜谱的条件

某一道草案拟晋升前，必须同时满足以下条件：

1. 关联候选的文化事实依据仍有效，且原创配方、替换槽位与不建议组合已完成结构审查；
2. 已完成该风险级别要求的真实试做，并保留完整试做日志与安全、质量修订证据；
3. 生肉、禽蛋、豆角、骨刺与过敏原等风险节点具备可核验的熟制或处置证据；
4. 已建立项目自有、可访问的第一方 canonical 来源页，包含生产菜谱所需的来源信息与署名；
5. 通过既有 Phase A 菜谱来源、schema、回归与人工评审闸门，包括 `node tools/check-recipes.mjs`；
6. 在当前 Phase A exit gate 全部满足并获得用户批准前，不得开始 150–200 道生产菜谱扩展，也不得将草案部署或提升到 production `main`。

## 检查命令

编辑草案或候选依据后，依次运行：

```bash
node tools/check-recipe-drafts.mjs
node tools/check-recipe-candidates.mjs
node tools/check-recipes.mjs
```

三个检查均通过只说明数据结构与当前闸门没有发现自动化错误，不替代真实试做、来源核验与人工审核。
