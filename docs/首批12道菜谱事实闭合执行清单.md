## 二、四合同怎样打勾

- **量**：固定份量、所有主要食材的数值和单位已结构化，且分别有来源支持；
- **液**：米、水或其他有效液体的数值、语义和适用器具边界已结构化；厂商水位线不擅自换算；
- **时**：预处理、烹饪、焖置等关键阶段和总时间已有明确合同；
- **安**：禽肉、猪肉、牛羊肉、蛋、海鲜或其他高风险食材有可验证的熟制与处理终点。

表中的 `□` 表示结构化合同尚未闭合。即使现有来源已经提到某个事实域，只要尚未形成完整、无冲突、可执行的合同，就不能打勾。

四合同全部闭合仍不自动等于 `executable`；真实身份、核心食材、关键流程、器具边界和来源冲突也必须同时通过审查。

## 五、来源冲突处理记录

发现来源冲突时，在对应菜谱下补一条记录，格式固定为：

```text
冲突事实：
来源 A 及其说法：
来源 B 及其说法：
更接近原产地/原技法的来源：
仍需厨房验证的变量：
当前裁决：未解决 / 原方合同已解决 / 家庭适配待实做
```

禁止取平均、拼接成第三套数值，或为了推进状态只保留其中一条说法。

## 六、逐道出口条件

每道菜只有同时满足以下条件，才能从本清单移入厨房验证：

- [ ] 真实名称和身份有独立来源；
- [ ] 核心食材与关键流程已经闭合；
- [ ] 用量合同闭合；
- [ ] 液体合同闭合；
- [ ] 时间合同闭合；
- [ ] 安全合同闭合；
- [ ] 器具边界明确；
- [ ] 所有来源冲突已解决或明确拆成不同版本；
- [ ] 家庭适配没有借用原器具参数；
- [ ] 人工内容审核通过。

厨房验证必须使用冻结的固定版本。每道至少有一次真实家庭制作成功并记录原话、实际时间、是否按步骤完成、是否出现夹生/过干/糊底或安全疑问，才能进入 `kitchen_observed`。
