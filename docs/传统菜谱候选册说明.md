# 传统菜谱候选册说明

## 这是什么

`tools/data/recipe-candidates.json` 是用于研究传统中国一锅主食方向的候选册。它只记录可追溯的传统事实与后续审核线索，是 research-only candidate ledger；它不是运行时数据源，不会被前端、worker 或本地代理作为生产菜谱加载。

候选册中的条目只能处于研究状态，不能据此生成、展示或宣称生产可用菜谱。

## 传统事实与受保护表达

菜名、地域、菜系归属、常见食材组合和宽泛技法模式，属于可核验的传统事实，可作为研究与溯源的对象。候选册只保留支持这些传统事实所必需的简要说明与来源链接。

不复制第三方页面的文字、图片、来源食材表、精确用量、烹饪时长、时间安排或完整菜谱步骤；也不把第三方的配方表达改写后当作项目内容。来源用于证明事实，不用于提供可复刻的配方。

自动检查会阻止结构化字段中的精确数量、营养声称和明显的有序步骤语句，但不能自动判定某段文字是否逐字复制或近似改写来源表达；这部分仍是人工审查责任。

## 何时能变成生产菜谱

候选升级前，项目必须独立编写原创标准配方，并明确所有 `substitution_slots` 中的替换对象与允许范围。之后必须完成一锅适配与食品安全复核，尤其确认熟制证据、交叉污染风险与不可一锅完成的环节。

每道生产菜谱还必须有项目自有的第一方 canonical 来源页面，包含可追溯的来源信息与署名。只有完成既有菜谱检查、回归闸门和人工评审后，候选才可进入生产菜谱库。

## 怎么检查

修改候选册后运行：

```bash
node tools/check-recipe-candidates.mjs
```

任何候选升级前，还必须运行：

```bash
node tools/check-recipes.mjs
```

## 风险分层

- low：食材与技法明确、可由常规一锅熟制安全完成的方向；仍需完成原创标准配方与常规审核。
- moderate：需要确认火候、吸水比例、分步下锅顺序或替换边界的方向；升级前需要额外试做与适配复核。
- high：可能涉及生禽肉、鸡蛋、海鲜、骨头、名称不明的地方食材或腌腊肉的方向；升级前必须逐项核验原料身份、可食部位、熟制证据、骨刺风险、盐分与保存风险，并进行额外安全审查和试做。

风险等级是审核优先级，不是自动放行。所有候选都必须通过上述生产升级闸门。
